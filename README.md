# 보낸 이미지 관리 1.0.0 (Marinara Engine 2.5.x)

채팅 중 캐릭터에게 **보낸 이미지**를 방별·날짜별로 모아 보고, 골라서 내려받거나 지우거나 WebP로 줄이는 개인 확장입니다. 엔진은 건드리지 않고 순정 채팅 API만 사용합니다.

## 왜 필요한가

채팅 중 보낸 사진은 갤러리 파일이 아니라 **메시지 안에 base64 글자로 통째로** 저장됩니다(메시지의 `extra.attachments`). 그래서

- 엔진에는 이것을 모아 보는 화면이 없고,
- 사진이 많은 방은 메시지 응답이 수십 MB가 되어 방 로딩이 무거워집니다.

이 확장은 그 사진들을 한 창에서 보고, 어느 방에 얼마나 있는지 확인하고, 필요 없는 것은 지우고, 남길 것은 WebP로 줄입니다.

## 여는 방법

화면 오른쪽 가장자리에 둥근 버튼이 하나 생깁니다. 누르면 창이 열리고, 끌어서 옮길 수 있으며 자리는 이 브라우저에 기억됩니다. **확장 서랍**을 쓰고 있으면 이 버튼도 서랍 안으로 들어갑니다. 창이 열려 있는 동안 버튼은 숨겨집니다.

## 창 구성

위쪽은 고정된 도구 줄이고, 아래만 스크롤됩니다. PC에서는 도구 줄의 빈 곳을 끌어 창을 옮기고 오른쪽 아래 모서리를 끌어 크기를 바꿀 수 있으며, 위치와 크기는 이 브라우저에 기억됩니다(화면 밖으로 나가면 다음에 열 때 안으로 당겨 옵니다). 창을 좁히면 제목 글자와 항목 이름이 자동으로 숨어 도구 줄이 한 줄로 남습니다. 폰에서는 전체 화면이고 도구 줄은 두 줄입니다.

| 도구 줄 | 설명 |
| --- | --- |
| 위치 | `모든 방` 또는 방 하나. 창을 열면 지금 들어가 있는 방이 기본이고, 방 밖(홈)에서 열면 `모든 방`입니다. 방을 고르면 바로 읽기 시작합니다. |
| 열 | 그리드 열 수. `자동`(창 폭에 맞춤) / 3열 / 4열 / 5열. 기억됩니다. |
| 최신순 / 오래된순 | 누를 때마다 바뀝니다. 기억됩니다. |
| 선택 | 선택 모드. 타일을 눌러 고르면 도구 줄이 `n장 선택 · 용량 / 전체 선택 / 다운로드 / WebP로 줄이기 / 삭제 / 취소`로 바뀝니다. Esc로도 나갑니다. |
| 읽기 버튼 | 방 하나일 때는 `다시 읽기`. `모든 방`일 때는 아직 안 읽은 방이 있으면 `안 읽은 방 읽기 (n)`, 다 읽었으면 `모두 다시 읽기`. |
| 상태 줄 | 사진 수·총 용량·형식별 장수, 마지막 작업 결과. 읽는 동안은 `읽는 중 n/총페이지 · 사진 n장`과 `중지`, 작업 중에는 진행 수와 `중지`. |

아래 그리드는 날짜별로 묶이고, `모든 방`에서는 방 제목 줄(이름 · 모드 · 장수 · 용량 · `읽기`/`다시 읽기`)이 먼저 옵니다. 지금 들어가 있는 방과 사진이 있는 방이 위로 옵니다. 아직 안 읽은 방은 지난번 읽은 기록(`n장 · 용량 (몇 시간 전 기준)`)을 보여 줍니다. 타일 왼쪽 아래는 형식과 용량(`PNG 1.2MB`), 오른쪽 아래는 `봇`(캐릭터 쪽 메시지의 첨부) 또는 `버전 n`(지금 보이지 않는 답변 버전 안의 사진) 표시입니다.

### 큰 보기

타일을 누르면 원본을 보여 줍니다. 좌우 화살표(키보드 ←→)로 넘기고, 아래에 방 이름 · 메시지 번호 · 보낸 시각 · 형식과 용량 · 픽셀 크기 · 파일명 · 캡션(엔진이 사진에 붙인 설명이 있으면)이 나옵니다.

- **메시지로 이동**: 지금 들어가 있는 방의 사진이면 창을 닫고 그 메시지로 스크롤하며 잠시 테두리로 표시합니다. 화면에 아직 없는 오래된 메시지면 엔진의 메시지 캐시에 과거 페이지를 50개 단위로 채운 뒤 엔진의 `이전 보기`를 눌러 그 메시지까지 넓힙니다(메시지 1,739개 방의 맨 처음 사진까지 약 10초, 엔진의 `#번호` 이동보다 빠름). 다른 방의 사진이면 메시지 번호를 복사해 주니, 그 방을 열고 메시지 검색창에 `#번호`를 붙여 넣으세요.
- **번호 복사**: `#번호`만 복사합니다.
- **다운로드**: 원본 그대로 내려받습니다. 파일명은 보낼 때 이름이 있으면 그것, 없으면 `보낸사진_날짜_번호.확장자`.
- **WebP** / **삭제**: 이 한 장만 아래 설명대로 처리합니다.

## WebP로 줄이기

선택한 사진을 브라우저에서 WebP로 다시 인코딩해 메시지 첨부를 교체합니다. 누르면 대화상자에서 다음을 정합니다.

| 항목 | 설명 |
| --- | --- |
| 품질 | 60~100, 5단위, 기본 85. 100은 무손실에 가까워 거의 줄지 않습니다. |
| 긴 변 상한 | 제한 없음 / 1280 / 1600(기본) / 2048px. 이보다 크면 비율을 지켜 줄입니다. |
| 예상 | 선택한 사진 중 표본 몇 장을 미리 인코딩해 `표본 n장: 전 → 후 (%) · 전체 예상` 을 보여 줍니다. 값을 바꾸면 다시 계산합니다. |

규칙:

- 첨부의 **`type`과 `data`만** 바꿉니다. 파일명·캡션(엔진이 사진에 붙인 설명) 등 다른 정보와 배열 순서, 다른 첨부(문서·생성 삽화)는 그대로입니다. 파일명 확장자도 바꾸지 않습니다.
- 결과가 원본보다 크면 그 장은 **그대로 둡니다**(결과에 `유지`로 집계). 이미 WebP인 사진은 건너뜁니다.
- 같은 사진이 **숨은 답변 버전(스와이프)** 에도 있으면 함께 바꿉니다. 지금 보이는 버전은 엔진이 메시지와 같이 맞춰 주고, 숨은 버전은 번호를 지정해 따로 바꿉니다.
- 적용 **직전에 서버에서 그 메시지를 다시 읽어** 사진이 읽었을 때와 같은지 확인하고, 그 사이 바뀌었으면 건너뜁니다. 적용 **뒤에도 다시 읽어** 새 사진이 들어갔는지 확인하며, 확인이 안 되면 실패로 알립니다.
- 열린 방에서 **생성이 진행 중**(보내기 버튼이 중지 아이콘)이면 — 엔진이 그 사이 첨부에 캡션을 써 넣을 수 있어서 — 작업당 한 번 최대 60초 기다리고, 그래도 계속이면 그 방 사진은 건너뜁니다. 다른 방 사진은 영향 없습니다.
- 원본은 어디에도 남지 않으므로 **진행 전 백업**(설정 → 백업)을 권합니다.

### 얼마나 줄어드나

엔진은 사진을 보낼 때 이미 한 번 줄입니다. 1.5MB를 넘거나 긴 변이 1536px을 넘는 사진(GIF는 항상)은 긴 변 1536px·품질 82의 JPEG로 바꿔 보내고, 그보다 작은 PNG는 그대로 보냅니다. 그래서 **JPEG는 WebP로 바꿔도 20~30% 정도만 줄고, PNG는 70~85% 줄어듭니다**. 대화상자의 예상치가 실제에 가깝습니다. (테스트 방 실측: PNG 5장 836KB → 68KB.)

## 삭제

선택한 사진을 메시지에서 뺍니다. **되돌릴 수 없으므로** 대화상자에서 장수·용량을 확인한 뒤 진행하세요.

- 메시지 자체와 글, 다른 첨부는 그대로 둡니다. 숨은 답변 버전에 있는 같은 사진도 함께 뺍니다. 엔진의 X 버튼은 지금 보이는 버전만 고치고 숨은 버전의 사본은 남기는데, 이 확장은 그것까지 뺍니다.
- 글 없이 사진만 있던 메시지는 글도 사진도 없는 빈 메시지로 남습니다(대화상자에 그 개수를 보여 줍니다). 메시지를 지우는 것은 대화 맥락이 바뀌는 일이라 하지 않습니다.
- 적용 직전·직후에 서버에서 다시 읽어 확인하는 것은 변환과 같습니다.

## 동시 작업 잠금

삭제·변환은 한 번에 하나만 돕니다. 같은 탭 안의 잠금에 더해 확장 저장소(서버)에 작업 표를 적어 두므로 다른 탭이나 기기에서 돌리면 "다른 탭이나 기기에서 작업 중"으로 거절됩니다. 저장소에 원자적 잠금이 없어서 "표를 쓰고 잠시 뒤 다시 읽어 내 표가 남았는지 확인"하는 방식이며, 둘이 거의 같은 순간에 시작하면 나중에 쓴 쪽만 진행합니다. 작업 중에는 60초마다 표를 갱신하고, 3분 넘게 갱신이 없는 표는 끊긴 것으로 봅니다. 거절됐을 때 상태 줄에 그 표와 `표 지우기` 버튼이 나오며, 그쪽 작업이 끝난 게 확실할 때만 누르세요. 새로고침으로 끊긴 내 작업의 표는 그 탭이 기억하고 있어 다음 작업이 그냥 넘어갑니다.

## 동작 방식

- 메시지는 엔진 화면과 같은 방식으로 **최신부터 50개씩 페이지 단위**로 받습니다. 한 번에 전부 받으면 큰 방은 응답이 수십 MB라 화면이 멈출 수 있기 때문입니다. 페이지 사이와 사진 사이마다 화면에 양보하므로 읽는 동안에도 창을 쓸 수 있습니다. (메시지 1,739개·사진 62장·20.8MB인 방 실측: 약 4초, 화면 멈춤 최대 0.06초)
- 사진마다 **긴 변 320px 썸네일**만 만들고 원본 base64는 버립니다. 수백 장의 원본을 메모리에 들고 있지 않기 위해서입니다. 큰 보기·다운로드·변환처럼 원본이 필요할 때만 그 메시지 한 개를 다시 받습니다.
- 답변 버전(스와이프)이 둘 이상인 메시지는 버전 목록도 읽어, 지금 보이지 않는 버전 안의 사진도 `버전 n` 표시와 함께 보여 줍니다. 숨은 버전에 같은 사진이 그대로 있으면 타일을 또 만들지 않고 본체에 묶어 두었다가 삭제·변환 때 함께 처리합니다.
- 방별 요약(장수·용량·읽은 시각)은 확장 저장소에 작게 기억해 두어 다음에 열 때 먼저 보여 줍니다.
- 서버 요청은 분당 420회 아래로 스스로 조절하고, 429가 오면 서버가 알려 주는 시간만큼 쉬었다가 다시 보냅니다. 변환 한 장에 요청 3~4회(다시 읽기 · 교체 · 확인)가 듭니다.
- 작업이 끝나면 열린 방의 메시지 캐시를 갱신해 새로고침 없이 바뀐 사진이 보입니다.

## 모아 보는 대상 / 아닌 것

- 대상: 메시지 첨부 중 `data:image/…` 형식(채팅 입력창으로 보낸 사진). 보낸 사람이 누구든, 어떤 확장이 넣었든 메시지 첨부에 이 형식으로 들어 있으면 보입니다.
- 아닌 것: 생성 삽화(갤러리 파일 주소 `url`로 연결됨 → 갤러리에서 관리), 문서·텍스트 첨부, 누들 게시글처럼 파일로 저장되는 이미지.

## 알아둘 점

- `모든 방` 읽기는 모든 방의 메시지를 전부 내려받는 일입니다(어느 메시지에 사진이 있는지 미리 알 방법이 없습니다). 방·페이지 단위로 나눠 받아 멈추지는 않지만, 큰 방이 많으면 시간과 데이터가 듭니다. 폰보다는 PC에서 하기를 권합니다.
- 사파리는 캔버스 WebP 인코딩을 지원하지 않아 변환이 실패로 집계됩니다. 크롬 계열에서 쓰세요.
- 확장만으로는 완전히 못 막는 것: 적용 직전 확인과 교체 사이의 아주 짧은 틈에 다른 기기가 같은 메시지를 고치는 경우, 두 기기가 0.7초 안에 동시에 작업을 시작하는 경우(엔진에 조건부 갱신·원자 잠금이 없음). 한 기기에서 쓰고 있을 때 작업하면 문제없습니다.

## 설치

마리나라 설정 → 개인 확장에서 zip을 올리고 승인(전체 페이지 접근 허용)합니다. 폴더에서 직접 올릴 때는 `extension.js`·`extension.css`를 올리고 `manifest.json`의 이름·설명을 맞춥니다.
